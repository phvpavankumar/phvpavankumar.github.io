UNDER THE HOOD

How a system like this works

01 · CAPTURE

Shelf-mounted cameras

Fixed cameras face the opposite shelf, each covering many slots. Sessions are sensor-driven, so compute is spent only when something changes.

02 · DETECT

Optimised detection

YOLO-family detectors compiled with TensorRT run at 15–20 FPS, classifying every slot: stocked, low, empty, or wrong product.

03 · RESOLVE

Multi-camera matching

LightGlue feature matching and calibrated geometry reconcile overlapping views, so one physical slot never becomes two conflicting answers.

04 · ACT

Serve & alert

Hot-reload model serving pushes events to staff devices in under 200 ms, and replenishment time is tracked from alert to restock.

WHAT I ACTUALLY BUILT

The engineering behind the demo

  • Multi-camera shelf-vision pipelines on YOLOv7/v9 with TensorRT acceleration and LightGlue feature matching — sub-200 ms responses at 15–20 FPS in production retail environments, with high-precision camera calibration.
  • Zero-downtime ML serving — hot-reload model APIs (Flask/Gunicorn) integrated with event streaming and document storage, fully containerised with observability built in.
  • End-to-end CI/CD for models, so detection improvements shipped like software, not like science projects.
  • The same discipline, upstream and down: the harder problem is rarely detection — it's calibration, definitions ("what counts as low?"), and making alerts trustworthy enough that staff act on them. That thread runs through everything I build, including my current enterprise AI work.
